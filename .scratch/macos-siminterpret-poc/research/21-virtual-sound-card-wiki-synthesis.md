## 2. 关键概念复述（与 T05/T06 一致）

**链路A（我→对方）**：
- 真实麦克风 → 识别翻译 → 翻译输出 → **虚拟声卡 A Input** → 会议软件「麦克风输入」选**虚拟声卡 A Output** → 会议传给对方

**链路B（对方→我）**：
- 会议软件「输出设备」→ **虚拟声卡 B Input** → 同传软件「对方声音输入」选**虚拟声卡 B Output** → 识别翻译 → 字幕/声音给我

**核心原则**：
> 「两个方向必须用**不同的虚拟声卡**，完全隔离，避免串音/死循环」

这与 T05 B1 总线隔离、T06 mirror device 思想完全一致 —— 大成子用大白话重述了相同原理。

## 3. **新增 · 3 个典型误区**（T06 调研中缺失的部分）

### 误区 1：翻译输出选同一个虚拟声卡 → 死循环

- **错误**：我的翻译输出选 Cable B Input（和对方声音输入的虚拟声卡一样）
- **后果**：我的翻译声音又被喂进虚拟声卡 B，被对方链路采集，**无限套娃 + 回声爆炸**
- **解决**：我的翻译和对方翻译必须用**不同的虚拟声卡**，完全隔离

### 误区 2：会议软件麦克风选真实麦克风 → 传原文

- **错误**：会议软件麦克风选真实麦克风
- **后果**：直接把**未翻译原文**传给会议，失去同传意义
- **解决**：会议软件麦克风必须选**我的翻译输出对应的虚拟声卡 Output**

### 误区 3：对方翻译输出选虚拟声卡 → 串音给会议

- **错误**：对方翻译输出选 Cable A Input（和我的翻译输出的虚拟声卡一样）
- **后果**：对方的翻译声音被喂进虚拟声卡 A，被会议软件采集，传给会议里的人，造成串音
- **解决**：对方翻译输出必须选**你的真实耳机**，只在本地播放

**对 PoC 的意义**：这 3 个误区应该作为 T12（macOS 总线隔离 PoC）+ T13（BlackHole 音频环路验收）+ T14（自开会议验收）的**自检 checklist 必检项**。T06 没明确警告这些，T05 也只在 README troubleshooting 里间接提过，本 wiki 直接列为 3 个 "❌" 误区。

## 4. **新增 · 用户问答确认 R4 单字幕模式可行**

评论 4月12日：
- 用户> 我：是否可以「我→同传→对方（翻译后声音 +字幕），对方→同传→我（只要翻译后字幕，对方原声）」
- 大成子回复> 可以。**配置完全自由**，声音不外放就行，组合完全随自己

**对 PoC 的意义**：
- R4 不强制要 TTS 输出，可以只显示双语字幕
- 如果未来要加 "R4 也走 TTS 让用户听到自己母语" 功能，是可选的 v1+ 增强
- 与 T16 + T18 推荐的 "R4 走 Doubao s2t mode 单 session" 完全一致 —— s2t mode 本身只输出字幕不输出音频，过滤 TTS 事件 350/351/352 即可
